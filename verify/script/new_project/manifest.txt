# new_project manifest - the single home of the new-chip classification:
# what a new project carries over, what it gets reset, what is regenerated.
# Read by `new_project.py bootstrap`. Paths are relative to the repo root.
#
#   carry <glob>                copied as-is
#   reset <path> <kind>         written fresh from the source file (kinds in new_project.py)
#   with:<flag> <glob>          carried only when bootstrap gets --with-<flag>
#   exclude <glob>              never copied (wins over carry)
#
# Not listed = not copied. That covers:
# - everything gen_uvm_env.py --guvc or file_manage.sh produces: env/, test/,
#   seq/, intf/, json/, uvc/<mod>/, the whole tb_top/ tree (assembly files,
#   module-private files and the user-maintained skeletons - filelists,
#   include.f, rtl_define.f, config/*.cfg - which the first --guvc writes
#   from the generator templates), utils/, sim/*, verify/ral/;
# - the chip-specific state: the design database (hdl/ is only a placeholder;
#   the real root is the design_root answer of /new-project), docs/modules/,
#   docs/features/<mod>/, docs/review/, docs/reports/<reports>, root README.md.
# The design file lists are filled by the /new-verification design-input step.
