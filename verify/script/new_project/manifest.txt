# new_project manifest - the single home of the new-chip classification:
# what a new project carries over, what it gets reset, what is regenerated.
# Read by `new_project.py bootstrap` and `new_project.py audit`. Paths are
# relative to the repo root. EVERY tracked file must match one class -
# `audit` fails on an unclassified file, and bootstrap refuses to run then,
# so a new framework file can never be forgotten silently.
#
#   carry <glob>                copied as-is
#   reset <path> <kind>         written fresh from the source file (kinds in new_project.py)
#   with:<flag> <glob>          carried only when bootstrap gets --with-<flag>
#   regen <glob>                not copied: produced by gen_uvm_env.py --guvc or file_manage.sh
#   state <glob>                not copied: chip-specific state of the source project
#   exclude <glob>              never copied (wins over every other class)
#
# The design file lists are filled by the /new-verification design-input step;
# the design database itself lives under the design_root answer of /new-project.
