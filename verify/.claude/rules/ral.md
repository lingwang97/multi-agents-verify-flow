# RAL model and the register table (flow behaviour)

The register table is a conditional dependency gated by the config knob `enable_ral`; no CSV is checked in. Canon for the knob: `verify/CLAUDE.md` ("Regenerating the environment"); flow settings: `.claude/rules/flow-scripts.md`.

- The RAL model `verify/ral/ral_reg_model.sv` is generated by the `RalGen` step of both flows (`utils/reg/gen_reg_model.py`) from the CSV at `$WSIM_REG_TABLE`, defined once in `script/sflow/flow_env.sh`.
- When a config enables `enable_ral`, the spec2json intake gate (`/new-verification`) asks the user for the CSV location; no flow script or instruction file names it.
- `wsim_oeda` runs RalGen only when the selected filelist references the RAL model, using `WSIM_PYTHON` - or `/usr/bin/python3` - whichever has openpyxl (OSS CAD Suite's python lacks it). It dies with a `WSIM_REG_TABLE` pointer if the CSV is missing.
- `wsim` skips RalGen with a warning when the CSV is absent; a RAL-compiling case then fails at compile time.
- Both regenerate when the model is older than the CSV or the generator (mtime). Output goes to `verify/ral/`: the model, `ral_reg_width` (widest-register width, injected into both flows by `testjson2lst.py`; 64 with a warning when absent) and a `<csv-name>.md` table view.
- `verify/ral/` is generated output: never edit or commit it; it is absent until a flow runs.
- Width derivation: RalGen (`gen_reg_model.py`) parses the CSV (field `BitEnd+1`, `Label REG_<n>`, byte span `(EndAddr-OffsetAddr+1)*8` - max of all three per register) and writes `verify/ral/ral_reg_width`; `testjson2lst.py` injects `max(64, derived)` into BOTH flows. Residual check when the real register table lands: confirm the derived value covers the real design's widest register - sliced registers depend on the Label/EndAddr columns being populated per slice; if they are not, the derivation undercounts and the number must be revisited.
